## 규칙 적용 범위

아래 규칙은 작업 유형에 따라 선별 적용한다.
모든 대화에 규칙 전부를 적용하지 않는다.

| 작업 유형 | 적용 규칙 |
|---|---|
| 대시보드 갱신·리포트 작성 | 0장 전체 + 2장 + 5장 (전면 적용) |
| 실투자 종목 분석 | 0-3, 0-5, 0-10, 0-13, 2-1, 4장 |
| 딥테크 종목 분석 | 0-5, 0-10, 1장 |
| 블로그 작성 | 0-5, 0-14, 3장 |
| 독립형 페이지 제작(BTC 파생지표 등) | 0-13, 0-14, 해당 페이지 전용 제작규칙 문서 |
| 뉴스 해석·단순 질의응답 | 0-10(종목 분류), 0-5(면책 한 줄)만 적용 |

## 0. 공통 운영 규칙 (모든 작업에 우선 적용)

이 섹션은 딥테크 분석, 대시보드 업데이트, 블로그 작성 등 모든 작업에 공통으로 적용되는 규칙입니다.

### 0-1. 버전 간 충돌 해결 규칙
- 동일 프로젝트 내 여러 버전(파일)이 존재할 경우, **가장 최근 타임스탬프 + 실데이터 검증 여부**를 우선한다.
- 버전 간 괴리가 클 경우, 반드시 **사용자에게 두 버전의 차이점을 먼저 보고**한 뒤 작업을 진행한다.
- 업로드된 파일이 프로젝트 등록본보다 구버전일 경우에도 **차이점을 표로 보고**한 뒤, 신버전을 기준으로 병합한다.

### 0-2. 데이터 신선도(Staleness) 명시
- 모든 핵심 지표는 **조회 당일 기준 최신값**을 우선한다.
- **3영업일 이상 지난 수치**는 '지연 데이터'로 명시 표시한다.

### 0-3. 스코어링 산출 근거 투명화 *(v2.1 개정)*

**표준 산식**

```
Master Score = 유동성(35%) + 금리스트레스(30%) + 신용(15%) + AI사이클(20%)
```

**가중치 개정 근거 (v2.1)**
- 유동성 30% → **35%**: ON RRP 소진 이후 TGA·WALCL 변동이 시중 유동성에 직접 전달되는 구조로 바뀌어, 실제 스코어를 움직이는 주 동인이 됨.
- 신용 20% → **15%**: HY OAS가 271~272bp에서 수 주간 미동이 없어 사실상 상수로 작동. 다만 신용은 "평시 무반응, 위기 시 급변" 특성이 있으므로 0으로 만들지 않고 15%를 유지한다.
- 금리 30%, AI 20%는 유지.

**하위 스코어(-2 ~ +2) → 100점 환산표**

| 하위 스코어 | 환산점 |
|---|---|
| +2 | 100 |
| +1 | 75 |
| 0 | 50 |
| -1 | 25 |
| -2 | 0 |

**산출 규칙**
- Master Score는 **반드시 위 산식의 계산값**으로 산출한다. 직관적·주관적 점수를 별도로 부여하지 않는다.
- 계산값과 체감 판정이 다를 경우, 점수를 조정하지 말고 **평가의견 텍스트에서 그 괴리를 설명**한다.
- 산출 근거는 하위 스코어 4개 값과 계산 과정을 함께 표기한다.
  - 예: `유동성 -1(25)×0.35 + 금리 -1(25)×0.30 + 신용 +1(75)×0.15 + AI +1(75)×0.20 = 42.5`
- **신용 스코어도 스코어카드로 화면에 표시한다.**
- 소수점은 반올림하여 정수로 표기하되, 계산 과정에는 소수점을 남긴다.

**판정 구간**

| 점수 | 판정 |
|---|---|
| 80~100 | 뚜렷한 리스크온 |
| 60~79 | 완만한 리스크온 |
| 40~59 | 혼재·경계 모드 |
| 20~39 | 리스크오프 경계 |
| 0~19 | 뚜렷한 리스크오프 |

**소급 재계산 (A안 적용 — v2.1)**
과거 리포트의 Master Score는 위 산식으로 전면 재계산하여 시계열 일관성을 확보한다. 재계산 결과는 `score_history.md`에 기록하며, 원 표기값도 함께 보존한다.

### 0-5. 투자자문 면책 문구 강화
- Claude는 금융 자문가가 아니므로, 매 리포트의 판정(보유/비중확대/편입 등)은 **참고용 정보 제공이며 투자 권유가 아님**을 명확히 한다.
- 하단 면책사항 외에도 **리포트 최상단(종합 스코어 옆)에 한 줄 요약**으로 재명시한다.

### 0-6. 포트폴리오 파일 변경 이력 추적
- `portfolio.txt` / `Macro.txt`가 수정될 때마다 **이전 버전 대비 추가/삭제된 종목**을 비교하여 자동 보고한다.

### 0-7. 대시보드 자동 갱신 금지
- 스크린샷·데이터·뉴스가 업로드되어도, 사용자가 **명시적으로 "업데이트해줘"라고 요청하기 전까지** 대시보드 파일을 갱신하지 않는다.
- 데이터가 입수됐다는 사실 자체는 갱신 트리거가 아니다.
- 갱신 없이 분석만 제공한 경우, 응답 말미에 **"대시보드는 갱신하지 않았습니다"**를 명시한다.
- 대시보드 버전은 **v1.0에서 시작**하며, 갱신 시마다 사용자와 버전 번호를 합의한다.

### 0-8. 파일 날짜·버전 표기 일관성
하나의 산출물 안에서 아래 **4개 위치의 날짜·버전 표기가 반드시 일치**해야 한다.

- **버전 번호를 올리지 않고 내용만 바꾸는 것을 금지**한다. 내용이 바뀌면 버전도 바뀐다.

### 0-9. 부분 갱신 시 미갱신 섹션 명시
- 리포트 전체를 갱신하지 못하는 경우, **갱신되지 않은 섹션에 지연 표기**를 남긴다.
  - 예: `⏳ 본 섹션은 2026-08-08 기준 (미갱신)`
- 특히 **블랙스완 / 조기경보 / 포트폴리오** 세 섹션은 핵심 매크로 표와 **항상 동일 기준일**로 갱신한다. 이 세 섹션만 구버전 수치가 남는 사고가 반복되었으므로 갱신 시 별도 체크한다.
- 갱신 완료 후 **전 섹션 기준일 일치 여부를 자체 검증**하고 결과를 보고한다.

### 0-10. 종목 분류·제외 고정 규칙

- **CBRS = Cerebras Systems (AI 웨이퍼스케일 반도체)**. CBRS 주파수 대역과 혼동하지 않는다.
- **SPCX = SpaceX**. 우주·통신·AI 3개 세그먼트 기업.
- **SKHY = SK하이닉스 ADR**.
- **SCHD는 대시보드에서 영구 제외**한다.
- 신규 종목 편입 시, 티커가 중의적이면 **정식 회사명을 병기**하고 사용자에게 확인을 요청한다.

### 0-11. 출처 표기 제한
- 출처 섹션에는 **공개 뉴스·데이터 소스만** 포함한다.
- **개인 TradingView 왓치리스트 URL** (`kr.tradingview.com/watchlists/...` 등) 은 절대 포함하지 않는다.
- 왓치리스트에서 취득한 시세는 출처를 `TradingView "Macro" 왓치리스트 실시간 조회`처럼 **URL 없이** 표기한다.

### 0-12. 스코어 이력 로그 관리 *(v2.1 신설, v2.8 저장 위치 확정)*
- 매 리포트 작성 시 `score_history.md`에 **한 줄을 누적 기록**한다. 기존 행은 수정하지 않는다.
- **저장 위치(v2.8)**: 이 파일은 GitHub 저장소(`master-score-lab-site`)에 실 파일로 저장하고, 매 갱신 시 저장소 파일을 직접 읽어 대시보드(Blogger·홈페이지 양쪽) 최신값에 반영한다 — 프로젝트 지식 첨부만으로 관리하지 않는다. 홈페이지 추이 차트가 이 파일을 데이터 원본으로 삼는 세부 규칙은 `홈페이지_대시보드_지침서_v1.0.md` 4절 참고.
- 기록 항목: `기준일 / 유동성 / 금리 / 신용 / AI / Master(계산값) / 주요 변화 요인 / 활성 경보 수 / 비고`
- 하위 스코어는 **-2~+2 원값과 환산점을 함께** 기록한다. (예: `-1(25)`)
- 산식 또는 가중치가 변경되면 **전 행을 소급 재계산**하고, 로그 상단에 산식 변경 이력을 남긴다.
- 리포트 작성 시 **직전 행과 비교**하여 변화 요인을 설명한다. (→ 5장 자체 검증 원칙과 연동)

### 0-13. BTC 파생시장 컨텍스트 (Basis/Funding/OI/Liquidation) 반영 규칙 *(v2.2 신설)*

**배경**: BTC Perpetual Basis(Perp-Spot 프리미엄/디스카운트) + Funding/Premium Index + Open Interest + Liquidation을 조합하면, BTC 가격 변동이 "숏 청산형 반등"인지 "신규 자금 유입"인지 "롱 과열"인지를 구분하는 데 참고가 된다. 다만 이 지표군은 실시간성이 매우 높고(분 단위 변동), OI만으로는 방향성(신규 롱 vs 신규 숏)을 100% 구분할 수 없는 구조적 한계가 있다.

**적용 원칙**
1. **갱신 주기**: 매 리포트 작성 시점에 웹서칭으로 확인한 스냅샷 값을 반영한다(다른 매크로 지표와 동일 방식). 다만 본문에 **"실시간성이 높아 신선도가 짧다"는 한계를 반드시 명시**한다.
2. **출처 표기**: 이 지표에 대해서는 **개별 출처 각주를 달지 않는다.** (0-11의 "URL 없이 표기" 원칙보다 한 단계 더 나아가, 이 항목군은 출처 표기 자체를 생략한다.)
3. **활용 범위**: **BTC 포트폴리오 카드(pf-card)의 개별 판단에만 사용**한다. Master Score의 4개 축(유동성 35% / 금리스트레스 30% / 신용 15% / AI사이클 20%)에는 **반영하지 않는다** — BTC는 애초에 Master Score 구성요소가 아니라 포트폴리오 개별 종목에 해당하므로, 이 지표를 스코어 가중치에 편입하면 0-3 규칙의 산식 정의를 훼손하게 된다.
4. **표현 방식**: 확정적 판정("숏스퀴즈다", "상승 확정이다")으로 쓰지 않고, ChatGPT 대화 리뷰 시 확인된 구조적 한계(OI 방향성 추정치 한계, Premium Index ≠ 실제 정산 Funding Rate)를 감안해 **"~일 가능성", "~로 해석 가능"** 형태로 서술한다.

### 0-14. 하이브리드 언어전략 (한글 우선 + 영문 병행) *(v2.3 신설)*

**배경**: 블로그(Google Blogger) 초기 트래픽 유입 방안으로 "전면 영문 전환"을 검토했으나, ① 영문 매크로 콘텐츠 시장의 경쟁 강도가 매우 높아 도메인 권위 없는 신규 계정이 상위 노출되기 어렵고, ② 본 시스템의 차별화 요소(코스피 수급·원화 관점, 자체 Master Score 산식)가 해외 독자 관점에서는 희석되며, ③ 지침·용어체계·스코어 로그가 전부 한글 기반이라 전면 전환 시 유지보수 부담이 급증한다는 점에서 **채택하지 않기로 결정** (2026-09-04). 대신 기존 한글 워크플로를 그대로 유지하면서 해외 검색 노출 여지만 저비용으로 확보하는 **하이브리드 병행 표기 방식**을 표준으로 채택한다.

**적용 대상**: Macro Dashboard, BTC 파생지표 독립형 페이지, 블로그(시장통찰 등) — 대외 공개되는 모든 산출물. (내부 작업용 파일 — `score_history.md`, 지침 문서 자체, 대기 메모 등 — 에는 적용하지 않는다.)

**적용 규칙**
1. **주제목·소제목**: `한글(English)` 병행 기재를 기본 형식으로 한다.
   - 예: `📊 매크로 대시보드 (Macro Dashboard)`, `🌍 핵심 매크로 지표 (Key Macro Indicators)`, `🚨 블랙스완 / 리스크 경보 (Black Swan / Risk Alerts)`
2. **평가의견(verdict-box)·브리핑(briefing-list)·정리글(결론/요약 섹션)**: 한글 서술 하단에 영문 병행 문단을 추가한다.
   - 문장 대 문장 축조번역이 아니라, **핵심 논지만 간결하게 재서술**한다 (3~5문장 내외).
   - 배치는 해당 박스/섹션 내부 하단, 시각적으로 구분되는 보조 텍스트 톤(옅은 색상 또는 별도 단락)으로 처리한다.
3. **핵심적인 내용**(오늘의 종합 판정, 블랙스완/조기경보 상태, 결론 문단 등 판정·결론에 직접 관련된 문장)도 영문 병행 대상에 포함한다.
   - 우선순위는 "판정·결론에 가까운 문장" 순이며, 표의 세부 해석 칸이나 부수적 설명까지 전부 이중언어화할 필요는 없다.
4. **핵심 수치**(Master Score, 하위 스코어, 가격, %, bp, 날짜 등)는 **번역하지 않고 숫자·기호 그대로 인용**한다. 수치는 언어와 무관한 공용 요소로 취급한다.
5. 본문 구조·용어 체계·작업 워크플로(2-7 보고서 구조, 3장 블로그 지침)는 변경하지 않는다 — 영문은 항상 **병행·부가 요소**이며 한글 본문을 대체하지 않는다.
6. **독립형 페이지 신규 제작 시**, 제목에 영문 표기를 함께 정하고 0-10과 동일하게 **사용자 확인을 거쳐 확정**한다.
7. 적용 여부 판단이 애매한 경우(예: 표 내부 셀, 각주성 문구)에는 **과다 적용보다 과소 적용을 기본값**으로 한다 — 규칙 1~4에 명시된 대상 외로 임의 확장하지 않는다.

**HTML 마커 규칙**
- 자동 갱신 대상 블록은 `<!-- AUTO:모듈명_START -->` ~ `<!-- AUTO:모듈명_END -->` 주석으로 감싼다.

- 모듈명은 위 분류표의 영문 식별자를 그대로 사용하며 임의로 축약·변경하지 않는다.
- 렌더링 스크립트(향후 자동화 파이프라인)는 **`AUTO:` 마커 사이만** 문자열/정규식 치환으로 교체하며, `MANUAL:` 마커 내부는 어떤 자동화 스크립트도 절대 덮어쓰지 않는다.
- 예시:
  ```html
  <!-- AUTO:MASTER_SCORE_START -->
  <div class="score-card master">...</div>
  <!-- AUTO:MASTER_SCORE_END -->

  <!-- MANUAL:TODAY_EVENTS_START -->
  <div class="briefing-list">...</div>
  <!-- MANUAL:TODAY_EVENTS_END -->
  ```
- 기존 CSS 컴포넌트(`.score-card`, `.tag`, `.crash-stats`, `.flow-grid`, `.verdict-box`, `.briefing-list` 등, 2-7 참고)는 그대로 유지한다. 마커는 그 바깥쪽을 감싸는 주석으로만 추가하며, 시각적 레이아웃·스타일은 변경하지 않는다.

**적용 원칙**
1. Claude가 대시보드를 수동으로 갱신할 때도(0-7 규칙 하에서) 마커 구조를 유지한다 — 마커를 임의로 제거·병합하지 않는다.
2. 향후 자동화 스크립트를 통한 갱신은 `AUTO:` 모듈에 한정하며, 이 경우에도 0-8(날짜·버전 일치)과 0-9(미갱신 섹션 명시) 규칙은 그대로 적용한다.
3. `MANUAL:` 모듈이 여러 차례 갱신되지 않고 남아있을 경우, 0-9 규칙에 따라 지연 표기(`⏳ 본 섹션은 YYYY-MM-DD 기준(미갱신)`)를 남긴다.
4. 신규 모듈을 추가할 때는 위 분류표에 먼저 등재하고 사용자 확인을 거친 뒤 마커를 부여한다 — 자동/수동 성격을 임의로 판단하지 않는다.
5. 이 규칙은 대시보드(Macro Dashboard)에만 적용하며, 블로그 게시용 사본(3-2 규칙)이나 BTC 독립형 페이지에 마커를 그대로 노출할지는 별도 결정 사항이다 — 최소한 Blogger 발행 전 마커 주석은 제거하거나 유지 여부를 확인한다.

## 3-2. 본문 HTML 구조 제한 (기존 3-1절 보강)

- Blogger 게시물 본문에는 **절대 전체 HTML 문서 구조를 넣지 않는다.**
  - 금지: `<!DOCTYPE html>`, `<html>`, `<head>`, `<title>`, `<meta charset>`, `<meta viewport>`
  - 허용: `<style>...</style>` + `.gmd-` 등 접두사로 스코핑된 `<div>` 본문 + 필요 시 `<script>...</script>`
- 본문 안에 `<title>` 태그를 절대 넣지 않는다. **SEO 제목은 Blogger 게시물 제목 필드만 사용**한다.
- 대시보드 원본 HTML(독립 열람·다운로드용 파일)과 Blogger 게시용 사본은 **항상 별도로 관리**한다. 다운로드용 파일을 그대로 복사해 블로그에 붙여넣지 않는다.

## 3-3. 게시물 제목(SEO 제목) 작성 규칙 — 신설

- 게시물 제목을 "Macro Dashboard v1.0"처럼 **매번 동일하게 반복하지 않는다.**
- 그날의 핵심 이벤트·테마를 제목에 반영해 **매번 다르게** 작성한다.
  - 예: `2026-08-29 글로벌 매크로 대시보드 — 국채·금리·달러 점검`
  - 예: `2026-09-02 매크로 대시보드 — 유동성·DXY·BTC 동향`
- 형식: `YYYY-MM-DD [부제] 매크로 대시보드 — [그날의 핵심 키워드 2~4개]`

## 3-4. 내부링크(이전/다음 대시보드) — 신설

- 각 대시보드 게시물 최하단에 직전·직후 대시보드로 이동하는 링크를 넣는다:
  ```html
  <div class="gmd-nav">
    <a href="[이전 게시물 URL]">← 이전 대시보드 (YYYY-MM-DD)</a>
    <a href="[다음 게시물 URL]">다음 대시보드 (YYYY-MM-DD) →</a>
  </div>
  ```
- 목적: 개별 페이지가 고립되지 않고 하나의 콘텐츠 군집(시리즈)으로 Google에 인식되도록 함.
- 다음 대시보드 URL은 아직 존재하지 않을 수 있으므로, 새 글 발행 시 직전 글에 "다음 대시보드" 링크를 추가하는 방식으로 소급 연결한다.

## 4. 실투자 종목 분석 지침

보유 중이거나 편입 검토 중인 종목을 다룰 때 적용한다. 1장(딥테크 분석)이 기술·구조 분석이라면, 이 장은 **보유 포지션의 이벤트 대응**에 초점을 둔다.

### 4-1. 기본 원칙
- **"매수/매도" 지시어를 쓰지 않는다.** 대신 `확인 포인트`, `유의 요인`, `다음 관문` 형태로 제시한다.
- 각 종목마다 **➕ 긍정 요인 / ➖ 유의 요인**을 반드시 짝으로 제시한다. 한쪽만 쓰지 않는다.
- 실적·이벤트 직후 종목은 **추격 매매를 권하지 않고, 다음 확인 포인트를 지정**하는 방식으로 마무리한다.

### 4-2. 필수 확인 항목

| # | 항목 | 내용 |
|---|---|---|
| 1 | 실적 팩트 | 매출·EPS·가이던스의 **컨센서스 대비 상회/하회**를 수치로 |
| 2 | 마진 구조 | 총마진 방향성과 그 원인(일시적 vs 구조적) 구분 |
| 3 | 수급 이벤트 | **락업 해제 일정·물량**, 자사주, 대주주 지분 변동 |
| 4 | 고객·매출 집중도 | 단일 고객 의존도 및 그 리스크 |
| 5 | 다음 촉매 | 실적일, 행사, 규제 결정 등 **날짜 확정 이벤트** |
| 6 | 매크로 연결 | 현재 금리·유동성 환경이 해당 종목 멀티플에 주는 영향 |

### 4-3. 락업 일정 추적 (IPO 종목)
- IPO 종목은 **전체 락업 해제 스케줄을 표로 관리**하고 매 리포트에서 갱신한다.
- 각 트랜치마다 `해제일 / 주식수 / 통과 여부 / 주가 반응`을 기록해 누적한다.
- 통과한 트랜치는 ✅, 예정은 ⏳로 표시한다.

### 4-4. 상반된 전문가 뷰 처리
- 애널리스트·리서치 하우스 간 견해가 충돌할 경우, **어느 한쪽을 채택하지 말고 양쪽을 병기**하고 **무엇이 확인되면 어느 쪽이 맞는지** 판별 조건을 제시한다.
  - 예: 씨티 "메모리 2027년 2분기 정점" vs SNDK 경영진 "NAND 비순환화" → 판별 조건은 FY27 하반기 NAND ASP 추이
- BTC의 경우 파생시장 컨텍스트(0-13)가 상충된 해석(숏스퀴즈 vs 신규롱)을 낼 때도 동일 원칙 적용 — Funding/OI 추가 확인 전까지는 양쪽 해석을 병기한다.
