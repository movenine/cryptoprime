# 홈페이지 대시보드 지침서 (Master Score Lab / GitHub Pages) — v1.0

> 이 문서는 `마스터_지침_클로드최적화_v2.7.md`(Blogger용 전체 대시보드 규칙)와 **별개로 관리**되는 문서입니다.
> 적용 대상: `master-score-lab-site` 저장소의 `dashboard.html`, `btc.html` 등 홈페이지 정적 페이지.
> 전체 상세 리포트는 Blogger(`https://movenine.blogspot.com/`)가 원본이며, 이 사이트는 그 요약판입니다.

---

## 1. 존재 이유 및 원칙

- 대상 독자는 **빠른 상황 파악**이 목적이며, 매매 타이밍을 얻으러 오는 게 아니다 (긴 매크로 지표로 타이밍을 잡는 건 지표 성격상 불가능하다는 점을 이미 확인함).
- **긴 글·중복 그래프는 금지**한다. 모든 문장은 1~2줄 이내로 압축하고, 더 필요한 정보는 `<details>` 토글이나 Blogger 링크로 위임한다.
- 정량 데이터(스코어·경보)는 즉시 노출, 정성 해설(왜 그런지)은 항상 **요약 1문장 + 펼쳐보기**의 2단 구조를 취한다.
- 이 페이지는 Blogger 전체 리포트의 **대체가 아니라 입구**다. 세부 지표 테이블, 국영문 병행 서술(0-14)은 이 사이트에 넣지 않는다 — Blogger 전용으로 남긴다.

## 2. 페이지 구조 (`dashboard.html`, 상단 → 하단)

1. 상단 바 — 기준시각(KST) + 버전, 우측에 "전체 리포트 보기" (Blogger 링크)
2. **히어로**: Master Score 숫자(대형) + 델타 + 판정 pill + 1문장 요약 + `<details>`로 전체 평가의견
3. 하위 스코어 4개 — 압축 카드 4열(모바일 2열), 점 색상 + 값만
4. **추이 차트** (Chart.js, 3절 참조)
5. 조기경보 — 배지 한 줄 (🔴N 🟠N), 표 형태 금지
6. 블랙스완 — 한 줄 요약
7. KOSPI — 한 줄 요약
8. BTC 파생시장 — 티저 카드 1개, 클릭 시 `btc.html`로 이동 (전체 내용은 그 페이지에)
9. 하단 — Blogger 전체 리포트 링크 + 면책 한 줄

이 순서를 임의로 바꾸지 않는다. 새 모듈을 추가할 때는 "정량 배지형"과 "정성 한 줄+details형" 중 어느 쪽인지 먼저 정하고 그 형식을 따른다.

## 3. 추이 차트 규칙 (Chart.js)

- 데이터 원본은 `score_history.md`(4절 참고) — 이 문서 밖의 값을 임의로 추정해 채우지 않는다. 로그에 없는 최신 포인트는 차트에 넣지 말고, 차트 아래에 "⏳ 아직 기록 전" 각주를 남긴다.
- **호버 동작**: `interaction: { mode: 'index', intersect: false }` — 그래프 위 어느 지점에 마우스를 올려도 그 시점의 5개 스코어(Master+하위4개)가 툴팁에 함께 표시되어야 한다.
- **선 스타일**: Master 선은 2px, 하위 4개는 1.25px. `borderCapStyle/borderJoinStyle: round`, `cubicInterpolationMode: 'monotone'`(오버슈트 방지), `tension: 0.4`.
- **포인트 마커**: 기본 반지름 2~2.5px, 호버 시 5~6px. `pointBorderColor`를 카드 배경색(`#14171f`)으로 지정해 "도넛 홀" 스타일을 만든다.
- **색상**: Master `#ffffff`(굵게), 유동성 `#fbbf24`, 금리 `#f87171`, 신용 `#34d399`, AI `#60a5fa` — 사이트 전체 색 토큰과 통일. 임의 변경 금지.
- **그리드/범례**: y축 그리드는 옅게(`rgba(255,255,255,0.05)`), x축 그리드는 숨김. 범례는 원형 점 스타일(`usePointStyle: true`)로 작게.
- 캔버스 높이: 데스크톱 240px, 480px 이하 모바일 200px.

## 4. `score_history.md` 데이터 소스 규칙 *(v1.0 — Brian 확정)*

- **`score_history.md`는 GitHub 저장소에 실 파일로 저장**하고, 매 갱신 시 이 저장소 파일을 직접 읽어서 차트/히어로 값에 반영한다 (더 이상 클로드 프로젝트 지식 첨부파일에만 의존하지 않는다).
- 저장 위치(예): 저장소 루트의 `/data/score_history.md` 또는 기존 규칙(0-12)대로 프로젝트 루트 — Claude Code 작업 시 실제 저장소 구조에 맞게 배치.
- 갱신 절차: ① 새 리포트 작성 시 `score_history.md`에 한 줄 추가(0-12 규칙 그대로 적용, 기존 행 수정 금지) → ② 이 저장소 파일을 커밋 → ③ `dashboard.html`의 차트 `labels`/`data` 배열에 같은 값을 반영 → ④ 커밋·푸시.
- 이 파일이 **차트의 유일한 원본(authoritative)**이다. 히어로의 Master Score 숫자도 이 파일의 최신 행과 반드시 일치해야 한다(불일치 시 0-8 규칙과 동일하게 오류로 간주).

## 5. 색상·폰트 토큰 (사이트 공통, `assets/site.css`와 동일)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#0b0d12` | 페이지 배경 |
| `--card` | `#14171f` | 카드 배경 |
| `--card-border` | `#262b38` | 카드 테두리 |
| `--text-dim` | `#9aa1b2` | 보조 텍스트 |
| `--green` / `--yellow` / `--red` / `--orange` | `#34d399` / `#fbbf24` / `#f87171` / `#fb923c` | 상태 색상 |

숫자 표기(스코어, 델타 등)는 `IBM Plex Mono` 폰트를 사용한다 — 본문 텍스트(시스템 폰트)와 구분해 "데이터"라는 인상을 준다.

## 6. 금지 사항 (Blogger 지침과의 차이점)

| 항목 | Blogger 대시보드 (마스터 지침) | 홈페이지 대시보드 (이 문서) |
|---|---|---|
| 국영문 병행 (0-14) | 적용 | **적용 안 함** — 한글 단문만 |
| 핵심 매크로 지표 11종 표 | 전체 노출 | **노출 안 함** — Blogger 링크로 위임 |
| 평가의견 길이 | 3~5문장 문단 | **1문장 + details 토글** |
| 포트폴리오/BTC 상세 | 해당 없음(BTC는 대시보드 내 pf-card) | BTC는 **티저 카드만**, 상세는 `btc.html` |

## 7. 향후 자동화 연동 시 참고

- Master 지침 2-10(AUTO/MANUAL 마커)은 Blogger 대시보드 전용 규칙이며, 이 홈페이지 문서는 아직 별도 마커 체계를 두지 않는다 — 페이지 전체가 상대적으로 짧아 필요성이 낮기 때문. 자동화 파이프라인이 실제로 이 페이지를 갱신하게 되면 그때 마커 도입 여부를 재검토한다.
- BTC 1시간 주기 자동화가 시범 적용되면, `btc.html`의 티저 카드 문구(`state` 텍스트)도 함께 자동 갱신 대상에 포함할지 별도 결정 필요 (현재는 수동).
