## 1. 존재 이유 및 원칙

- 대상 독자는 **빠른 상황 파악**이 목적이며, 매매 타이밍을 얻으러 오는 게 아니다 (긴 매크로 지표로 타이밍을 잡는 건 지표 성격상 불가능하다는 점을 이미 확인함).
- **긴 글·중복 그래프는 금지**한다. 모든 문장은 1~2줄 이내로 압축하고, 더 필요한 정보는 `<details>` 토글이나 Blogger 링크로 위임한다.
- 정량 데이터(스코어·경보)는 즉시 노출, 정성 해설(왜 그런지)은 항상 **요약 1문장 + 펼쳐보기**의 2단 구조를 취한다.
- 이 페이지는 Blogger 전체 리포트의 **대체가 아니라 입구**다. 세부 지표 테이블, 국영문 병행 서술(0-14)은 이 사이트에 넣지 않는다 — Blogger 전용으로 남긴다.

## 2. 페이지 구조 (`dashboard.html`, 상단 → 하단)

1. 상단 바 — 기준시각(KST) + 버전, 우측에 "전체 리포트 보기" (Blogger 링크)
2. **히어로**: Master Score 숫자(대형) + 델타 + 판정 pill + 1문장 요약 + `<details>`로 전체 평가의견
3. 하위 스코어 4개 — 압축 카드 4열(모바일 2열), 점 색상 + 값만
4. **추이 차트** (Chart.js, 3절 참조)
5. 조기경보 — 배지 한 줄 (🔴N 🟠N), 표 형태 금지
6. 블랙스완 — 한 줄 요약
7. KOSPI — 한 줄 요약 + 배지형 보조지표 최대 2~3개 (2-1절 참고, v1.1 신설)
8. BTC 파생시장 — 티저 카드 1개, 클릭 시 `btc.html`로 이동 (전체 내용은 그 페이지에)
9. 하단 — Blogger 전체 리포트 링크 + 면책 한 줄

이 순서를 임의로 바꾸지 않는다. 새 모듈을 추가할 때는 "정량 배지형"과 "정성 한 줄+details형" 중 어느 쪽인지 먼저 정하고 그 형식을 따른다.

### 2-1. KOSPI 배지 압축 규칙 *(v1.1 신설)*

Blogger 마스터 지침의 `KOSPI_FLOW` 모듈(v2.9 개정 예정, 5개 세부항목)을 홈페이지 축약형에 그대로 노출하지 않는다. "한눈에 보고 클릭 유도"라는 1절 원칙에 따라 다음 우선순위로 **최대 2~3개만** 배지·보조텍스트로 압축한다.

| 우선순위 | 항목 | 압축 표기 예시 |
|---|---|---|
| 높음 | 밸류에이션 위치(정점 대비) | 히어로 스코어 옆 보조 수치: `정점대비 -OO%` |
| 높음 | 확인포인트 캘린더 | 가장 임박한 이벤트 1개만: `D-OO 삼성전자 실적` |
| 높음 | 신용융자·레버리지 잔고 | `신용융자 OO조 (정점대비 -OO%)` |
| 중간 | 외국인 채권 vs 주식 순매수 | 방향 화살표: `주식▼ 채권▲` (압축 어려우면 보류) |
| 낮음(생략) | 원-엔 스프레드 연동 메모 | 생략 — "상세보기 → Blogger 대시보드" 링크로 대체 |

- KOSPI 한 줄 요약 안에 값을 `·`로 이어붙이는 방식으로 2~3개까지는 실제로 무리 없이 들어간다 — 2026-09-16 갱신에서 `6,717.97 (+0.5%) · 외국인 순매도 축소(-3.9조→-1.4조원) · USD/KRW 1,370.96원(+0.59%)` 3개 항목을 이 방식으로 이미 반영한 전례가 있다.
- **자동화 방식**: BTC 티저 카드와 같은 시간당 자동 갱신은 적용하지 않는다. KOSPI 배지는 Master Score와 동일하게 **대시보드 갱신을 사용자가 명시적으로 요청할 때만 동기화**한다(0-7 원칙과 동일).
- USD/KRW처럼 Macro collector 시트에 없는 값은 매 갱신 시 웹서칭으로 확인한다(마스터 지침 2-1 출처 표, v2.8 참고).
- ⚠️ 이 저장소의 마스터 지침은 v2.8이며 `KOSPI_FLOW` 5개 세부항목의 공식 정의는 아직 등재되어 있지 않다. Blogger 쪽 v2.9가 확정·병합되면 위 표의 항목명·기준을 대조해 갱신할 것.

## 3. 추이 차트 규칙 (Chart.js) *(v1.1 — 2026-09-16 실 배포분에 맞춰 개정)*

- 데이터 원본은 `score_history.md`(4절 참고) — 이 문서 밖의 값을 임의로 추정해 채우지 않는다. 로그에 없는 최신 포인트는 차트에 넣지 말고, 차트 아래에 "⏳ 아직 기록 전" 각주를 남긴다.
- **표시 라인**: Master Score **한 줄만** 화면에 그린다(색 `#38bdf8`, 굵게 3px). 하위 스코어 4개는 투명 데이터셋(`borderWidth:0, pointRadius:0`)으로 유지해 화면에는 안 보이지만 아래 호버 동작에는 계속 포함시킨다 — 범례도 `filter`로 Master만 노출한다. *(v1.0의 "5개 라인 동시 표시" 규칙을 대체)*
- **호버 동작**: `interaction: { mode: 'index', intersect: false }` — 그래프 위 어느 지점에 마우스를 올려도 그 시점의 5개 스코어(Master+하위4개) **원점수**가 툴팁에 함께 표시되어야 한다. 툴팁 콜백에서 축의 원값(0~100)을 `+1 (75점)` 같은 로그 표기로 되돌려 보여준다.
- **배경 판정 구간 띠**: 0-3 산식의 판정 구간(뚜렷한 리스크온 80~100 / 완만한 리스크온 60~80 / 혼재·경계 40~60 / 리스크오프 경계 20~40 / 뚜렷한 리스크오프 0~20)을 배경 색 띠 + 우측 라벨로 항상 표시한다. 커스텀 `beforeDraw` 플러그인으로 구현하며 외부 라이브러리를 추가하지 않는다.
- **채우기 없음**: Master 라인 아래 영역 채우기(그라데이션)는 넣지 않는다 — 라인만 표시한다.
- **선 스타일**: `borderCapStyle/borderJoinStyle: round`, `cubicInterpolationMode: 'monotone'`(오버슈트 방지), `tension: 0.4`.
- **포인트 마커**: Master 기본 반지름 3px, 호버 시 7px. `pointBorderColor`를 카드 배경색(`#0b0d12`)으로 지정해 "도넛 홀" 스타일을 만든다.
- **Y축**: 0~100 고정(원래 척도 유지, 0 중심으로 바꾸지 않는다), `stepSize: 20`으로 판정 구간 경계와 그리드선을 맞춘다.
- **그리드/범례**: y축 그리드는 옅게(`rgba(255,255,255,0.05)`), x축 그리드는 숨김. 범례는 Master 항목만 원형 점 스타일(`usePointStyle: true`)로 작게 노출한다.
- **출처 각주**: `score_history.md` 외에 실데이터를 제공한 원본(예: Macro collector 구글시트, 클로드 데일리 리포트)도 함께 명시한다.
- 캔버스 높이: 데스크톱 240px, 480px 이하 모바일 200px.

## 4. `score_history.md` 데이터 소스 규칙 *(v1.0 — Brian 확정)*

- **`score_history.md`는 GitHub 저장소에 실 파일로 저장**하고, 매 갱신 시 이 저장소 파일을 직접 읽어서 차트/히어로 값에 반영한다 (더 이상 클로드 프로젝트 지식 첨부파일에만 의존하지 않는다).
- 저장 위치(예): 저장소 루트의 `/data/score_history.md` 또는 기존 규칙(0-12)대로 프로젝트 루트 — Claude Code 작업 시 실제 저장소 구조에 맞게 배치.
- 갱신 절차: ① 새 리포트 작성 시 `score_history.md`에 한 줄 추가(0-12 규칙 그대로 적용, 기존 행 수정 금지) → ② 이 저장소 파일을 커밋 → ③ `dashboard.html`의 차트 `labels`/`data` 배열에 같은 값을 반영 → ④ 커밋·푸시.
- 이 파일이 **차트의 유일한 원본(authoritative)**이다. 히어로의 Master Score 숫자도 이 파일의 최신 행과 반드시 일치해야 한다(불일치 시 0-8 규칙과 동일하게 오류로 간주).

## 6. 금지 사항 (Blogger 지침과의 차이점)

| 항목 | Blogger 대시보드 (마스터 지침) | 홈페이지 대시보드 (이 문서) |
|---|---|---|
| 국영문 병행 (0-14) | 적용 | **적용 안 함** — 한글 단문만 |
| 핵심 매크로 지표 11종 표 | 전체 노출 | **노출 안 함** — Blogger 링크로 위임 |
| 평가의견 길이 | 3~5문장 문단 | **1문장 + details 토글** |
| 포트폴리오/BTC 상세 | 해당 없음(BTC는 대시보드 내 pf-card) | BTC는 **티저 카드만**, 상세는 `btc.html` |

## 7. 향후 자동화 연동 시 참고

- Master 지침 2-10(AUTO/MANUAL 마커)은 Blogger 대시보드 전용 규칙이며, 이 홈페이지 문서는 아직 별도 마커 체계를 두지 않는다 — 페이지 전체가 상대적으로 짧아 필요성이 낮기 때문. 자동화 파이프라인이 실제로 이 페이지를 갱신하게 되면 그때 마커 도입 여부를 재검토한다.
- BTC 1시간 주기 자동화가 시범 적용되면, `btc.html`의 티저 카드 문구(`state` 텍스트)도 함께 자동 갱신 대상에 포함할지 별도 결정 필요 (현재는 수동).
